Identity & Access after the merge

Your slice became the system-wide login. Your API, roles, screens and parent-link flow all stayed; the storage underneath them changed, and three security holes are closed.

What was kept

Yours, unchanged in shape
  • The role set learner · guardian · author · moderator · administrator. TK and TC renamed their 'admin' to match yours.
  • Username sign-in for learners, email for everyone else; /me, /roles, the link-code flow, SignInScreen, ParentLinkScreen, authStore with restoreServerSession.
  • scrypt password hashing with timingSafeEqual, and your openapi documentation.
  • Your test cases, re-pointed at the database.

What changed, and why

ChangeWhy
Accounts, sessions and links moved from JSON files to Postgres. AuthAccountStore and ParentLinkStore are gone; AccountMethods, SessionMethods and ParentLinkMethods now hold SQL.Five other slices need a real users row to point a foreign key at: content authors, learner settings, moderator decisions. data/auth-store.json gave them nothing to reference, and two concurrent signups could collide on nextUserId.
The gate no longer accepts x-user-id / x-user-role headers, in the gate or in getRouteUser.Anyone could send x-user-role: administrator and read every linked child. With ownership checks now on content, a spoofable identity would have made them meaningless.
An invalid token answers 401.The catch had // next(error) commented out and then returned, so the request hung with no response at all. With 30-second sessions, any tab left open hit this.
Signup accepts learner and guardian only; staff come from npm run seed:staff.Public signup accepted any role, so anyone could register as an administrator.
AUTH_SECRET is required, with no 'dev-secret-only' fallback, and signatures compare in constant time.A known fallback secret lets anyone mint a token for any account.
Sessions last 7 days, link codes 10 minutes.30 seconds and 1 minute were demo settings; they make every other slice look broken.
Signed-in routes moved after the gate (apply_auth_session_api_routes) with RoleGuard; signup, login and /roles stay before it.The scaffold's rule: everything after the gate needs a session. Your parent-link routes were checking roles by hand instead.
Migrations renumbered to 100_users_sessions.sql and 101_parent_linking.sql; first_name / last_name replace name, and age is gone.089/091 sat either side of the shared 0xx range. Your code already used first and last names while the table had one name. Age duplicated the date of birth in TK's learner_settings, so that is now the one place it lives.
The child progress report returns empty counts.It returned invented lessons and scores. The shape is unchanged, so when the learner slice lands progress tables only the query changes.
The router guard reads meta.requiresAuth and meta.roles.It was a hardcoded set of two route names, so no other slice could protect its own screens.
npm run dev is back to tsx watch; tmp/auth-gui-render/*.png, 9_to_11_September and TESTING_COMPLIANCE.md were removed from the repo root.Hot reload was lost when dev switched to build-then-run.

How much of this is new code

Worth knowing

The API, the rules and the screens are yours. What was rewritten is the storage layer underneath them: AccountMethods, SessionMethods and ParentLinkMethods are now SQL against Postgres rather than reads and writes of a JSON file. Feature for feature it does the same things, but it is a substantial amount of code you did not write, and backend/scripts/seedStaff.ts is new outright.

Please read both before building on them. Nothing here was a redesign of your slice; if a decision looks wrong, it is yours to change.

Your unit tests for the JSON store were replaced rather than deleted: every case they covered is now an integration test against Postgres.

Running it

git fetch origin
git switch integration

# backend/.env needs one new line
AUTH_SECRET=any-long-random-string

cd backend && npm install
docker compose up -d
npm run migrate        # run against a FRESH database: the migrations were renumbered
npm run seed:staff     # creates author@lingolearn.test, moderator@…, admin@… (password: lingolearn-dev)
npm run dev

cd ../frontend && npm install && npm run dev

Learners and guardians sign themselves up. Author, moderator and administrator accounts only come from npm run seed:staff, so nobody can sign up as staff.
