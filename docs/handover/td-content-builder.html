Content builder after the merge

The builder itself is unchanged in shape. What changed is everything around it: content now belongs to an author, it has a title and a language, and three new list routes serve the slices that read it.

What the other slices needed, and now have

NewWho reads it
GET /api/content/getMyContentThe author dashboard, which listed ten hard-coded rows.
GET /api/content/getPendingContentThe review queue, which had seven hard-coded rows.
GET /api/content/getApprovedContent?level&language&childFriendlyOnlyExplore. For a learner it also runs the onboarding slice's access check.
ContentMethods.setReviewedStatus(client, id, status)Moderation, inside its own transaction with the decision row.
title, language, child_friendly columnsEvery list screen needed a title; the learner's target language filters content; the under-13 gate needed one honest flag instead of three invented "audience" fields.

What was fixed in the slice

  • No auth at all. Create, edit, delete and submit are author-or-administrator, and lockEditableOrThrow checks ownership: another author gets 403, not a silent edit. author_id comes from the session and is NOT NULL.
  • Reading rules. An author reads their own work, a moderator anything submitted, any signed-in reader approved content.
  • Levels disagreed in three places — the database allowed 1–10, the API 1–6, the UI showed A1–C1. Everything is 1–6 now, matching the taxonomy's levels table.
  • Submit never checked media. It accepted an image with no file and no alt text, and audio with no file, which would have rendered as nothing for a learner. The three copies of the validation are now one module that both the routes and the submit screen use.
  • A draft could not be reopened from the UI (LNG-32). It opens at /content-builder/:contentId, and there is a "Start a new draft" action after submitting, which was impossible without a page refresh.
  • Rejected content reopens as a draft on the first edit, which is how an author answers a moderator.
  • Tags come from the taxonomy API rather than a hard-coded array, so they stay in step with MO's vocabulary. The tag tables moved out of 300_content.sql into his 400_taxonomy.sql, per the migrations README's 4xx range.
  • Audio blocks really upload now and play the file: MO's upload button and player were ported into your audio bar. Image blocks still take a typed link, as they did before — uploading images is media's slice to add.

This slice was advanced, not only integrated

Your own slice

Unlike the others, the content builder gained real features during the merge: three list routes, the title, language and child-friendly columns, ownership checks, the draft-reopen route, the new-draft action and the audio upload field. That was deliberate — four slices read this slice, and each gap here was blocking someone else — but it is new work, not just wiring.

Decisions that were made for the group

  • The block format stays yours: content: $ContentBlock[][] with 'Text' | 'Image' | 'Audio' and no block ids. NS's renderer used lowercase types and required ids; hers was adapted, because your shape already has backend validation and the most tests behind it.
  • Kind stays derived from the blocks. QUESTION_BLOCK_TYPES is still empty, so everything is a story until question blocks exist — that is Sprint 2 and it blocks TK's placement test.
  • Language values are english and zulu, the same words TK's learner_settings.target_language already stored.

What is yours to do next

  • Question block types (LNG-37, LNG-38) — TK's placement ladder needs them.
  • Author preview (LNG-41): the learner slice's renderer now exists, so the builder can reuse it instead of the disabled Preview button.
  • A size limit on content: express.json is set to 50 MB and nothing caps pages, blocks or string lengths.
