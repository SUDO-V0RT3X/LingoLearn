LingoLearn: one system

Six branches merged into integration, with the conflicts settled and the mock data replaced by real queries. This is the group summary; each person has their own page.

Where it stands

  • Everything is on origin/integration. main is untouched: the last step is a merge request from integration into main, which someone other than the author should approve.
  • Every slice is merged. Six branches became one app with one login, one content table, one tag vocabulary and one set of role names.
  • 124 backend tests, all against a real Postgres database, and 285 frontend tests. Both type checks are clean, including the test files.
  • The seven security holes listed in the merge plan are closed.

What the merge did, and did not, do

The job was to make six branches into one coherent system out of the parts that already existed — not to build anyone's remaining features. Nothing was advanced in the onboarding or learner slices; both were ported, fixed and rewired, and what is left is still theirs.

Two exceptions remain, each because the join could not close without them. They are marked in the person's own page, and either can be handed back:

  • Moderation — the decisions table and the approve/reject and author-feedback routes. Deciding was not implemented at all, so nothing could ever reach approved and Explore would always have been empty.
  • Identity — the same features, but the storage rewritten from JSON files to SQL, plus a staff seed script.

Two other additions were written and then taken out again, because integration did not need them: an image upload, which only repeated the audio path that already existed, and a second block renderer for the review screen, which now reuses the learner's. Around 200 lines came back out.

The content builder was deliberately advanced, because four slices read it and each gap in it was blocking someone else.

What the whole system does now

                          │
   author writes content   │   under 13? a guardian must redeem a link code first
        │                  │
   submit for review  →  moderator queue  →  approve / reject with a reason
        │                                          │
   rejected: the author edits, which reopens it     approved
                                                    │
                                              learner Explore  →  reader
                                              (their level, their language,
                                               child-friendly if under 13)

7 migrations, 30 documented API routes and 13 screens. The API is browsable at /api/docs.

What is still missing

  • Progress tables (5xx). Nothing records what a learner has read or passed. This blocks level locking, progress bars, the level-up challenge and the guardian's progress report, which returns empty counts today.
  • Question block types. QUESTION_BLOCK_TYPES is empty, so all content is a story and the placement ladder has nothing to ask.
  • Placement (learner_levels, placement_attempts) and the moderator's user management screens.
  • Uploads are not tracked in the database, so there is no safe way to delete one.
  • A known flake: on a loaded machine a backend test occasionally times out waiting on the database. Rerunning passes, and no test has ever failed on a wrong result — worth watching rather than ignoring.
