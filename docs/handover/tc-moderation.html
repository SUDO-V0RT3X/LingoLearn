Moderation after the merge

Your screens, sorting and decision rules are in, now reading real submitted content and writing real decisions. The merge used LIN-39 and LIN-38 rather than demo-combined.

Which branches were merged

Not demo-combined
  • LIN-39-review-detail then LIN-38-review-queue were merged. Both have the role guards switched on.
  • demo-combined was left out: a335295 comments out the queue guard and 8578787 quietly comments out the detail guard too. Its "v2, with fixes" commit contains no fixes — the diff is exactly LIN-38's own changes.
  • Of the two identical-looking "add unit tests for LIN-38" commits, the later one is the one that works; the earlier has a bad import and the file pasted twice.

What was kept

Yours
  • Both screens, the sort and filter controls, and the waiting-time column.
  • QueueSortFilter, WaitingTimeFormatter, DecisionValidator, DecisionMessageBuilder and their tests. Pulling logic into small named helpers is the habit the rest of the project should copy.
  • The detail screen reloading when the id in the URL changes.

New code written in your slice, not just rewiring

Written for you, yours to own

Deciding was not implemented anywhere: confirming a decision did console.log and an alert(). Without it nothing could ever reach approved, so the learner's Explore would always have been empty and the merge could not be shown working end to end. So these were written during the merge:

  • backend/migrations/600_moderation.sql — the content_reviews table.
  • ReviewDetailMethods.decideContent and POST /api/reviewDetail/decideContent/:id.
  • ReviewDetailMethods.getFeedbackForAuthor and GET /api/reviewDetail/getMyFeedback, which is what the author's dashboard reads.
  • Nothing else. A preview component was written and then removed again: the review screen now renders the learner slice's own BlockRenderer, so a moderator sees exactly what a learner sees and the project has one renderer rather than two.

Read them before you build on them, and change anything you disagree with — this is your slice. If you would rather have written it yourself, say so and it can be reverted to a documented gap instead.

Your tests

The old ones asserted the placeholder: seven rows, and 401 because the gate was a no-op. They are replaced by backend/test/integration/moderationRoutes.test.ts, which signs in as an author, submits content, then as a moderator lists the queue, opens it, approves, and rejects — including that a rejection without a reason is refused and that a second decision is 409. Your four frontend helper specs still pass unchanged.

Running it

cd backend && npm install
docker compose up -d
npm run migrate        # run against a FRESH database: the migrations were renumbered
npm run seed:staff     # author@lingolearn.test, moderator@…, admin@… (password: lingolearn-dev)
npm run dev

cd ../frontend && npm install && npm run dev

Learners and guardians sign themselves up. Author, moderator and administrator accounts only come from npm run seed:staff.
