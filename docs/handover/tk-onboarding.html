Fixes made inside your code

  • Date of birth was shifting by a day. pg turns a DATE into local midnight, so in SAST a stored 2005-01-14 came back as 2005-01-13T22:00:00Z. That broke <input type="date">, moved the date back one day on every save, and made a learner a day younger at the 13th-birthday boundary. Both queries now read to_char(date_of_birth,'YYYY-MM-DD'), and SELECT * was replaced by named columns.
  • The parent-link check reads TS's table. learnerAccess queried parent_links … status = 'active', which no longer exists; a row in parent_child_links is the link, because identity only writes one when a guardian has redeemed a code.
  • Setup-complete is a server question now. localStorage 'lingolearn_setup_complete' followed the browser rather than the learner: the same learner on another laptop looked new, and clearing it let an under-13 learner past the block. A settings row exists or it does not.
  • A blocked under-13 learner is no longer signed out. They are sent to the parent-linking screen to generate a code, which is the thing that unblocks them.
  • Paths are verb-named: getSettings, saveSettings, getAccess.

Your rule now gates real content

GET /api/content/getApprovedContent calls your requireLearnerContentAccess for any learner:

  • No settings row → 403, setup must be completed first.
  • Under 13 with no guardian linked → 403.
  • Under 13 with a guardian → allowed, but only child_friendly content, whatever the request asks for.

Content has a language column using your words (english, zulu), so learner_settings.target_language filters it directly.
