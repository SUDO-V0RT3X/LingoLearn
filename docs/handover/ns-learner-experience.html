Learner experience after the merge

Your reader, block renderer and Explore are now part of the app, reading real approved content. The branch itself was not merged — the app was ported out of version12_FinalTesting by hand.

Why the branch was not merged

Three blockers
  • It replaced the main App.vue with your standalone one, which removed <RouterView> and the navigation. Merging it would have broken every other slice's screens.
  • Thirteen copies of the app (version0–version12), about 9.8 MB and 52,000 lines, each with its own package.json. Only version12_FinalTesting was ported; nothing in the earlier ones was missing from it.
  • main.ts imported App.vue through C:/Users/sigwa/Desktop/vite-vue/src/, a path that only exists on your laptop. The "locations" commit fixed that in two files but not this one.

Nothing of yours was thrown away: the components, the recorder and your tests were moved into frontend/src/features/learner_experience/, in the same layout every other slice uses.

What was kept

Yours
  • DocumentViewer, BlockRenderer, PageNav, the Text, Image and Audio blocks.
  • useMicRecorder, RecordingBar and ComparisonBar — record-and-compare is the best pedagogy idea in the project, and it cleans up its Blob URL on unmount.
  • The wallpaper picker, still a per-browser preference.
  • Explore's search and filter behaviour, and 56 of your tests: DocumentViewer, BlockRenderer, the three blocks, and Explore.

What changed, and why

ChangeWhy
Tabs became routes: /explore and /read/:contentId, learners only.The rest of the app is routed, and a learner needs to be able to link to a lesson.
The catalogue comes from getApprovedContent and one document from getContent, through a Pinia store, instead of 23 hard-coded rows and fetch('/c1-document-paginated.json').Those JSON files were never in the app. The fetch failed, the error was never caught, and the viewer kept showing the bundled Lighthouse example — which is why opening anything appeared to work.
Block types are 'Text' | 'Image' | 'Audio', and blocks have no id. Your renderer keyed on block.id and matched lowercase 'text'.The content builder's shape is what the database stores and what the backend validates. Against real data your blockSchema.js would have rejected every document and the renderer would have shown "No renderer yet" for every block.
Image and audio sources go through MediaDataSource.resolveUrl.Uploads are stored as relative paths like /uploads/audio/<uuid>.mp3, so the page has to put the API origin back.
The learner is the signed-in one. Language comes from their onboarding settings, and the child-friendly lock from the server's access check.Explore always used the default {age: 24, level: 2, guiChoice: 'ven'}, because the real learner was never passed in.
Approved-only is enforced by the server, and the reader refuses anything not approved.A learner could otherwise open a draft by id.

Left out on purpose, because the data does not exist

These were dropped rather than faked. Each needs a table nobody has built:

  • Level locking ("your level and below, locked above"). Nothing stores a learner's level yet — that is TK's learner_levels, still to come. The level dropdown remains as a plain filter.
  • Progress bars, the "continue reading" card and the level-up card — they need a progress table, which is your 5xx range and your next piece of work.
  • The has-audio filter: catalogue rows deliberately do not carry the pages, so the list cannot tell. It needs a flag from the server.
  • passRate, flags, authorNote, page count — no column anywhere.
  • Your Testing screen ("under construction"), the unused blocks (Author, Content, Pages, Quote, Title), the QA panel, and App.spec.js, which tested the tab and fetch mechanics that routing replaced.

The microphone recording is never uploaded — it stays in the browser. If pronunciation feedback should be kept or scored, that needs a storage decision and a consent conversation first, not just a route.

Nothing here was built out for you

Port only

No feature was added to this slice during the merge. Files were converted to TypeScript, re-pointed at the real API and moved into the standard folder layout; several features were removed because the data behind them does not exist yet. Everything in the next section is still yours to build.

What is yours to do next

  • Progress tables (5xx): content progress and test attempts. Everything above depends on them, and so does the guardian progress report, which currently returns empty counts.
  • Tags are returned on every catalogue row (chosenTags) and shown on the cards — a theme filter is a small addition if you want it back.
  • The lesson content itself is real now, so the example document and its media are no longer needed.

Running it

git fetch origin
git switch integration

# backend/.env needs one new line
AUTH_SECRET=any-long-random-string

cd backend && npm install
docker compose up -d
npm run migrate        # run against a FRESH database: the migrations were renumbered
npm run seed:staff     # author@lingolearn.test, moderator@…, admin@… (password: lingolearn-dev)
npm run dev

cd ../frontend && npm install && npm run dev

To see Explore with something in it: sign in as the seeded author, write a lesson and submit it; sign in as the seeded moderator and approve it; then sign up a learner, finish setup, and open Explore.
